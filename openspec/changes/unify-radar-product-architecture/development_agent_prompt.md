- 按 tasks.md 顺序推进。先完成来源源码、版本、必要依赖与现有能力基线核实，再迁移实现。不凭其他产品名称猜测可删除的依赖，不假定复制目录就能运行。

## 必须落地的三项审查修订

1. **模块与事务**：按 design 的数据归属表和依赖方向实施。跨模块用例由 workflows 协调同一 session，参与域不得自行提交。来源/审核变更与撤回事件、总结保存与 ready 事件保持原子性；保留锁顺序、生成后指纹复核、事件版本和游标语义。不是只把文件移动到新目录。
2. **持续运行引擎**：按 design 2.3 接管录制/弹幕启动、停止、异常退出和恢复；保留稳定会话/分片身份、完整文件交付、单飞控制、进度持久化、去重和转录偏移。观众弹幕仍与主播转录分离，业务重试和协议重连各负其责。
3. **迁移接续与回退**：保留待消费任务的名称/参数/队列兼容及存量媒体引用，不能清队列或把任务统一重置。隔离演练暂停派发、在途交接、唯一执行者、状态接续和新版本写入后的回退。sent/dead/unknown 保持现有语义，unknown 不因迁移重发。

保留现有已实现功能、页面行为、视频时间/数据日期口径、身份、证据、审核规则及推拉契约。不要夹带其他待实施提案、框架升级、UI 重设计、通用工作流平台或与本需求无关的重构。复用代码保留实际来源、版本及必要说明。

## 开发自检与证据

- 运行受影响的现有检查、前端构建和适用的 lint/测试；记录命令、执行目录、版本、退出结果和原有失败，不能删检查或降低断言使结果变绿。
- 在不提供旧产品源码目录、虚拟环境或管理页面会话的支持环境中，按产品自己的安装入口验证已支持链路。实际来源、模型或硬件不可用时，准确标注未验证项，不能以模拟结果替代真实独立运行证据。
- 使用隔离的数据库、队列、媒体和接收端验证视频/直播、弹幕、转写、审核总结、拉取和推送。推送须有接收端读回证据，不能只以 HTTP 2xx 表示已正确保存。
- 覆盖事务失败与审核资格变化、未完成/重复分片、异常恢复、旧任务和文件接续、事件游标、投递状态，以及新写入后回退接续；用 design 中的演练步骤组织证据。
- 不接入生产队列，不向真实订阅者补发，不停用生产服务，不删除旧生产数据库、媒体或环境。
- 运行 OpenSpec 严格校验及 diff 检查。规范校验、构建通过和业务验收分别报告，不能互相替代。
