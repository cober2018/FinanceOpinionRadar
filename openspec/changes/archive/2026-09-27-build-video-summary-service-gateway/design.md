## Context

参考项目 `DreamOAgents/frontend/src/views/DataManagement/APIs/index.vue` 的真实服务目录从接口返回条目，左栏检索/选择，右栏展示参数、输出字段和试读；凭证另有入口。其代理端点不支持页面试读，发布审批和监控卡片含本地演示数据。雷达现有 `OpenApiPage` 只有说明块、API Key 表、推送渠道表和投递表，后端已有视频总结拉取与 Webhook，无需新网关服务。

## Goals / Non-Goals

**Goals:**

- 将“视频审核后总结”呈现为一个服务条目，在详情页切换“拉取”和“推送”交付方式。
- 两种视图各有与实际契约一致的参数/字段说明；拉取可用临时 API Key 真实试读，推送可管理已有订阅与查看投递。
- Key 签发、可恢复的暂停/启用与永久吊销在拉取详情中可用；渠道订阅/启停及人工对账在推送详情中可用。

**Non-Goals:**

- 不复制参考项目的 Vue/Element Plus 代码，不新建动态注册表或通用 API 发布平台。
- 不加入演示审批、虚构网关状态、伪造推送事件或自动创建 API Key。
- 不更改对外读取 API 路径、事件载荷、签名、数据库表结构和 worker。

## Decisions

1. 在雷达现有 React 页面实现双栏服务目录；左侧只登记“视频审核后总结”，右侧顶部提供“拉取 / 推送”切换。切换只改变详情展示，不触发启停请求、不创建第二份资产、不改变凭证或订阅状态。参考项目仅供信息架构和交互借鉴。
2. 拉取视图以 `GET /open/v1/video-summaries` 为主，展示 `cursor`、`page_size` 与响应字段；单视频路径为同一服务的兼容查询说明。试读仅在操作者主动提交后，从浏览器同源请求现有开放 API；API Key 只保留在页面内存，不写入持久化存储、不出现在 URL/日志/代码示例。HTTP 失败和空 `items` 如实展示。
3. 推送视图展示 Webhook 接收方式、`ready`/`withdrawn`、事件载荷和签名头，并在该视图内复用现有渠道配置、订阅开关、投递/对账。现有“测试渠道”是连通性测试，必须标清并不代表产生真实视频总结事件；真正投递结果只能由现有投递记录证实。
4. 拉取视图保留现有 API Key 创建与永久吊销，并增加单个 Key 的 `active ↔ disabled` 可恢复状态管理。管理路由仅允许这两种状态互转，已吊销 Key 不能恢复；每次状态变更记录审计。现有开放接口只接受 `active` Key，因此 `disabled` 自动拒绝访问，无需修改对外读取契约或表结构。推送视图保留现有 Webhook 渠道与视频总结订阅的启停。各操作都由视图内的独立按钮触发；数据加载失败时显示未知状态，不将未知渠道数显示为 0。

页面层级：`开放接口 → 服务目录 → 视频审核后总结 → [拉取 | 推送]`。拉取视图显示 GET 路径、鉴权、请求参数、返回字段、在线试读与 API Key 的创建/暂停/启用/吊销；推送视图显示 Webhook 事件、载荷与签名、渠道/订阅启停、最近投递和对账。两种视图不同时展开各自的操作区，避免把 Webhook 误写成 GET 接口。

## Risks / Trade-offs

- 静态字段清单随后端变更可能过期 → 实施前逐项对照拉取路由、`serialize_event` 和 Webhook 签名代码；变更接口时同步页面契约。
- 浏览器试读涉及 API Key → 只在本地页面状态暂存、使用请求头发送到当前雷达服务，不在 URL、localStorage 或示例片段回显。
- 推送无真实接收方时无法端到端验证消费 → 页面区分“未配置”“已订阅”“已投递”“结果未知”，不声称下游已消费。

## Migration Plan

增加一个 API Key 状态管理端点并调整雷达控制台开放接口布局，沿用现有数据库。先验证 Key 状态鉴权、前端构建与实际页面，再切换本地控制台静态产物；回退需同时恢复上一版前端和管理端点。

## Open Questions

本提案按参考项目的服务目录与真实交互实现；发布审批、统一动态注册和网关级监控若未来需要，另立需求。
