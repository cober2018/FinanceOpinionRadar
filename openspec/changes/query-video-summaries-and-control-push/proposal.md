## Why

现有开放接口能按事件游标拉取审核后视频总结，却不能按视频时间、主播和当日最新条数直接检索；运营也无法从单视频观点页明确选择自动或手动推送。内部下游需要可预测的取数口径和可追踪的投递动作。

## What Changes

- 增加当前有效视频总结的三种查询：视频时间范围、指定主播的指定日期全量、当天最近 N 条。三者均以视频时间筛选及排序，和总结完成时间分开。
- 保留现有 `/open/v1/video-summaries` 事件游标流，用于增量同步与撤回；新查询不返回撤回事件或历史版本。
- 在开放接口的“拉取”详情展示三个查询方式、参数、时间口径和真实试读。
- 在单视频观点总结处增加“推送”入口，区分未来总结的自动推送订阅和当前已审核总结的手动推送；共用现有 Webhook 签名、投递记录和去重语义。
- 在“推送”详情显示自动订阅、手动投递及撤回的状态；不在页面编辑或发布接口、事件定义。

## Capabilities

### New Capabilities

- `video-summary-time-query`: 按视频时间查询当前有效视频总结的三种读取方式。
- `video-summary-manual-delivery`: 单视频审核后总结的手动投递与自动订阅协同、去重和失效通知。

### Modified Capabilities

- `video-summary-open-interface-catalog`: 拉取/推送详情需展示新增查询模式和投递控制。

## Impact

- 涉及开放 API、视频总结查询服务、现有 Webhook worker、单视频观点页和开放接口页。
- 复用已有 API Key、视频总结事件和投递表；是否需要局部持久化扩展由设计确定，不改变既有事件游标契约。
- 本变更不包含真实下游接入配置、历史数据补推或生产发布。
