## Context

现有 `GET /open/v1/video-summaries` 按不可变事件 ID 递增，包含 `ready` 和 `withdrawn`；它服务增量同步，不能把事件创建时间当作视频时间。`VideoSummaryEvent` 保存版本与载荷；`current_event` 能核对当前审核状态。自动推送按渠道 `summary_enabled` 和订阅起点投递，`VideoSummaryDelivery` 按渠道和事件唯一。单视频观点页已有总结区，但无独立推送操作。

## Goals / Non-Goals

**Goals:** 三种基于视频时间的当前有效总结查询；单视频手动推送和既有自动订阅的清晰选择；失效、去重和投递结果可追踪。

**Non-Goals:** 改变现有事件游标/签名载荷；逐观点推送；编辑接口定义；历史批量补推；真实下游配置或生产发布。

## Decisions

1. **独立查询端点**：新增 `GET /open/v1/video-summaries/query`，以 `mode=range|creator_day|today_latest` 选择互斥参数。保留原事件流。比较过扩展旧事件端点（游标及撤回语义易混淆）和前端过滤（无法完整分页），独立端点对调用方更明确。继续使用 `X-API-Key`。
2. **统一时间口径**：只以事件载荷 `video_time` 作为筛选/排序时间。普通视频取公开发布时间，直播取已有开播时间；`time_basis=unknown` 或无时间的记录不进入时间查询，也不以总结完成时间补值。时间范围采用带时区 ISO 8601 的 `[from,to)`；日期及“今天”按 `Asia/Shanghai` 自然日 `[00:00,次日00:00)`。按 `video_time DESC, item_id DESC` 稳定排序。若需要同日全量超出单页，使用不丢不重的游标分页；今天最近 N 条限制 1–200。昨天视频今天完成总结：不属于今天查询，但属于完成后事件流及订阅推送。
3. **只返回当前有效版本**：查询基于每个视频最新事件且仅当前仍符合审核条件的 `ready` 版本，返回既有事件载荷的主播、视频时间、时间依据、总结、版本和事件 ID。指定主播使用稳定 `creator_id`，由 SourceItem→SourceAccount→Creator 关联；不按同名主播文本匹配。查询参数无效返回 422，非当前有效/时间缺失不返回。不要把历史版本或 withdrawn 当作普通查询结果。
4. **推送动作分层**：观点页“推送”打开同一弹层：自动模式管理所选渠道对**未来**视频总结事件的订阅；手动模式为**当前这条**已审核有效总结选择启用的通用 HTTPS Webhook 渠道并排队一次。自动开启从最新事件起点开始，不补发当前视频；若需当前视频立即发送，选择手动。手动请求再次核对当前版本，未审核、已失效或未生成时拒绝；响应返回排队/已投递等可核查状态。
5. **复用投递并保持撤回闭环**：手动请求在 `VideoSummaryDelivery` 以 `(channel_id,event_id)` 幂等入队；worker 用现有签名、安全校验、有限重试与投递记录处理，不在 HTTP 请求中同步发网。为区分手动/自动在投递记录添加最小 `trigger` 标记；自动既有记录默认自动。手动 ready 已成功或结果未知时，后续 withdrawn 即使渠道未订阅自动事件也须发往同一渠道；结果未知不得无声忽略，应保留对账状态。若排队后 ready 已非当前有效，worker 不发送过期正文并记录取消/失效，避免下游先收到陈旧版本。已投递同一版本不因手动重复发送；失败/未知按现有重试及人工对账规则处理。
6. **界面**：开放接口仍是一项服务的“拉取 / 推送”详情切换。拉取详情展示原增量流及新三种查询参数/试读，推送详情展示订阅设置和真实投递记录；观点总结处提供推送入口，模式选择本身不改变状态，只有确认操作才调用管理接口。

## Risks / Trade-offs

- [时间来源为空或被更正] → 排除时间查询，保留原事件流与 `time_basis`，不伪造视频时间；来源更正后以最新版本为准。
- [日期边界与下游时区不同] → 明示 `Asia/Shanghai`，范围查询要求带时区；下游可用已有事件游标流补漏。
- [手动与自动并发] → 数据库唯一约束及渠道级锁合并同一事件投递；未知投递结果保留对账，不盲目重复。
- [查询量增长] → 数据库筛选、稳定游标和单页上限；必要索引随迁移评估，禁止把全部事件读到应用内再过滤。

## Migration Plan

先完成 schema/服务/API 与 worker，再接 UI；增加投递触发标记的向前兼容迁移。验证现有事件游标响应、单视频查询、签名及撤回语义不回归。部署需迁移后更新 API/worker/web；回滚应用前先停新手动入队，保留已入队和投递日志供对账。生产发布、真实渠道联调不属于本次本地实施。

## Open Questions

无阻断项。手动投递的具体渠道由操作员当次选择；“今天”固定为 `Asia/Shanghai`，以财经业务日口径展示。
